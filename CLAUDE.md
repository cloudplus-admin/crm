# CLAUDE.md

Памятка для Claude и разработчиков. Подробности в `docs/`: [архитектура](docs/architecture.md),
[интеграции](docs/integrations.md), [лицензии](docs/licenses.md).

## 1. Что за проект и для кого

CRM-система для малого и среднего бизнеса Узбекистана, продаётся как **облачная подписка (SaaS)**:
одна установка, много компаний-клиентов, данные каждой изолированы. Только CRM (не ERP): контакты,
лиды/заявки, сделки, воронки, задачи, история общения. Главная ценность: все входящие из мессенджеров
(Telegram, Instagram, WhatsApp) и звонки в одной карточке клиента.

## 2. Стек и решения

| Решение | Почему |
|---|---|
| **FastAPI** + Pydantic | JSON API для React и для открытого API клиентам из одного кода; OpenAPI бесплатно; async удобен для webhooks мессенджеров. Админку Django не используем, поэтому его плюсы не нужны. |
| **React + TypeScript + Vite** | Интерфейс уровня SaaS (инбокс, канбан воронки), отдельный от API. |
| **PostgreSQL 16**, SQLAlchemy 2, Alembic | Надёжность, JSONB для сырых сообщений, Row-Level Security для изоляции компаний. |
| **Мультиарендность: общая БД + `company_id`** | Дешевле обновлять и обслуживать, чем базу на клиента. Изоляция в двух слоях: фильтр в запросах и политики RLS в PostgreSQL. |
| **Celery + Valkey** (план) | Очередь синхронизации и повторных попыток. Celery: BSD-3. Valkey (BSD-3) вместо Redis 7.4+, у которого лицензия больше не BSD. Выбор подтвердить, когда появится первая фоновая задача. |
| **Docker / Docker Compose** | Одинаковая среда разработки и продакшена. |
| **Хостинг в Узбекистане** | Закон о персональных данных требует хранить данные граждан РУз на серверах в стране. **Нужна проверка юристом** до первого клиента. |
| **Без AGPL** | Своё ядро, Frappe CRM и другой AGPL-код не используем. Каждая зависимость проверяется и вносится в `docs/licenses.md`. |

## 3. Структура (сейчас и план)

```
app/            сейчас: main.py (API), models.py, schemas.py, db.py, seed.py
  core/         план: настройки, БД, безопасность, мультиарендность (tenant context)
  modules/      план: contacts, leads, deals, pipelines, tasks, activities, inbox, billing
  connectors/   план: base.py (интерфейс), registry.py, telegram/, instagram/, whatsapp/, ...
  workers/      план: задачи Celery (синхронизация, повторы)
frontend/       React: src/LeadsPage.tsx, src/api.ts, src/i18n.ts (RU/UZ), src/styles.css
migrations/     Alembic
tests/          pytest
docs/           архитектура, интеграции, лицензии
```

## 4. Команды

```bash
make up && make seed          # Docker: приложение + БД, http://127.0.0.1:8000
make install                  # локально: .venv и npm ci
make db; make dev-api; make dev-web   # разработка: БД в Docker, API :8000, фронт :5173
make test                     # pytest на SQLite; make test-pg на PostgreSQL
make lint                     # ruff check, ruff format --check, tsc --noEmit
make format                   # автоформат Python
make migration m="описание"   # новая миграция Alembic (проверять руками)
cd frontend && npm run build  # сборка фронтенда
```

## 5. Коннекторы и волны интеграций

Каждая платформа — отдельный модуль-плагин в `app/connectors/<имя>/`, реализующий общий интерфейс:
подключение (`connect`/проверка учётных данных), приём входящих (webhook или polling), отправка
исходящих, нормализация сообщений и контактов во внутренний формат. Вся синхронизация идёт через
очередь с повторами и идемпотентностью; соответствие внешних ID хранится в таблице `external_refs`.
Подробно: [docs/architecture.md](docs/architecture.md#коннекторы).

- **Волна 1**: Telegram (первый), Instagram, WhatsApp Business.
- **Волна 2**: Click, Payme, Uzum; SMS Eskiz, PlayMobile; IP-телефония.
- **Волна 3**: Google Sheets/Calendar, IMAP/SMTP, Excel, открытый API и webhooks, 1С, Odoo.

Перед реализацией любой интеграции **проверить актуальную документацию** и обновить
[docs/integrations.md](docs/integrations.md). Условия API по памяти не писать.

## 6. Правила кода и тестов

- Каждая таблица с данными клиента имеет `company_id`; любой запрос идёт через контекст компании.
  Тест на изоляцию (компания A не видит данные B) обязателен для каждого нового модуля.
- Секреты и токены только из переменных окружения или хранилища секретов. Не в коде, не в логах,
  не в ответах API (токены маскировать).
- Изменения схемы только миграциями Alembic.
- Любая новая зависимость: проверить лицензию, записать в `docs/licenses.md`. GPL/AGPL нельзя.
- Демо-данные только вымышленные: телефоны `+998 00 ...` (код не выдан операторам).
- Python: ruff (настройки в `pyproject.toml`), типы в сигнатурах. Фронтенд: строгий TypeScript.
- Интерфейс на двух языках: русский и узбекский (латиница). Все тексты UI только через
  `frontend/src/i18n.ts`, новый текст добавляется сразу в оба словаря.
- Перед коммитом: `make lint` и `make test` зелёные.
